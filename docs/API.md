# API

Machine-readable spec: [openapi.json](openapi.json) (generated by `make docs-api`; also served live at `/openapi.json` and `/docs`).
All responses are JSON. Errors always look like `{"error": {"code": "SNAKE_CASE", "message": "..."}}`.

## Conventions
| Topic | Behaviour |
|---|---|
| Auth | `Authorization: Bearer isk_...` (API key) or a JWT from `POST /v1/auth/token`. `/admin/*` uses `X-Admin-Key`. |
| Roles | `viewer` read + ask; `analyst` + sync and train; `admin` + sources, keys, account, promote/rollback. Key `scopes` can only narrow a role. |
| Tenancy | A key belongs to one account. Ids belonging to another account return `404 NOT_FOUND`. |
| Request id | `X-Request-ID` is echoed (or generated). Include it in bug reports. |
| Pagination | `limit` (1-200) and `offset`; lists return `total`. |
| ETag | Heavy GETs return `ETag`; send `If-None-Match` to get `304`. ETags change when the account's data, models or settings change. |
| Idempotency | `Idempotency-Key` header on `POST /v1/sources`, `/v1/sync`, `/v1/models/train`. Replays return the first response with `Idempotent-Replay: true`; reuse with a different body is `409 IDEMPOTENCY_MISMATCH`. |
| Rate limits | Token bucket per key (and per IP); `429 RATE_LIMITED` with `Retry-After`. Defaults: 600/min, burst 60. |
| Cold start | Rankings and scores say `method: "heuristic"` plus `cold_start_reason` when data is too small for a model. |

## Routes
| Method and path | Needs | Purpose |
|---|---|---|
| `GET /v1/health` | none | liveness |
| `GET /v1/ready` | none | readiness (database check, LLM configured or template fallback) |
| `GET /metrics` | optional `METRICS_TOKEN` | Prometheus metrics |
| `POST /v1/auth/token` | any key | exchange API key for JWT (needs `JWT_SECRET`) |
| `GET /v1/account` | `data:read` | current account |
| `GET /v1/accounts/{account_id}` | `data:read` | own account only, else 404 |
| `PATCH /v1/account` | admin | rename, settings (`sla_first_response_s`, `vip_revenue_threshold`, `label_horizon_days`) |
| `GET /v1/api-keys` | admin | list keys (never the secret) |
| `POST /v1/api-keys` | admin | create key (secret shown once) |
| `DELETE /v1/api-keys/{key_id}` | admin | revoke |
| `GET /v1/sources` | `data:read` | list sources |
| `POST /v1/sources` | admin | register a funnels or conversations source |
| `GET /v1/sources/{source_id}` | `data:read` | one source |
| `PATCH /v1/sources/{source_id}` | admin | rotate key/pepper, pause |
| `DELETE /v1/sources/{source_id}` | admin | delete source and its landed rows |
| `POST /v1/sync` | analyst | trigger sync job (`?wait=true` runs inline) |
| `GET /v1/sync/status` | `data:read` | watermarks, last status per resource, recent jobs |
| `GET /v1/jobs/{job_id}` | `data:read` | one job |
| `GET /v1/join` | `data:read` | cross-app join coverage and pepper warnings |
| `POST /v1/identity/bridge` | admin | link the same people across sources whose identity peppers differ, from a contact list you supply (calls accumulate; `"replace": true` starts over; see [APPROACH.md](APPROACH.md#combining-the-two-apps)) |
| `GET /v1/identity/bridge` | `data:read` | number of bridged contacts per source |
| `GET /v1/rankings/funnels` | `data:read` | funnels ranked by expected uplift (`?rerank=true`) |
| `GET /v1/rankings/steps` | `data:read` | steps ranked (`?funnel_id=`, `?rerank=true`) |
| `GET /v1/leads/scores` | `data:read` | open leads ranked by conversion probability (`min_score`, `limit`, `offset`, `scope=open|all`) |
| `POST /v1/leads/score` | `data:read` | score one `contact_key`, `email` (hashed in memory) or `features` |
| `POST /v1/leads/score/batch` | `data:read` | score up to `BATCH_MAX_ROWS` (5000) feature vectors or known contact keys in one vectorised call |
| `GET /v1/rankings/conversations/open` | `data:read` | open conversations ranked by priority with explanations |
| `GET /v1/segments` | `data:read` | contact segments |
| `GET /v1/anomalies` | `data:read` | deduplicated anomalies (`since_days`) |
| `GET /v1/insights` | `data:read` | findings + narrative (`?narrate=false` forces template) |
| `POST /v1/ask` | `ask` | natural-language question over analytic tools |
| `GET /v1/models` | `data:read` | model versions with metrics and cards |
| `POST /v1/models/train` | analyst | train (`model_types`: `lead_conversion`, `sla_breach`, `segments`) |
| `POST /v1/models/{version_id}/promote` | admin | make a version active |
| `POST /v1/models/types/{model_type}/rollback` | admin | re-activate the previous version |
| `GET /v1/models/types/{model_type}/drift` | `data:read` | PSI drift (`recent_days`) |
| `GET /admin/accounts` | admin key | list accounts |
| `POST /admin/accounts` | admin key | create account and first admin API key |
| `PATCH /admin/accounts/{account_id}` | admin key | disable/enable, rename, settings |
| `GET /admin/accounts/{account_id}/usage` | admin key | row counts and LLM usage |
| `POST /admin/accounts/{account_id}/retrain` | admin key | enqueue (or `?wait=true` run) training |
| `POST /admin/accounts/{account_id}/refresh-profiles` | admin key | fan the Parquet profile refresh out over N `profiles` jobs (`shards`) |
| `GET /admin/models` | admin key | model versions across accounts |
| `GET /admin/jobs` | admin key | recent jobs (`status`) |

## Examples
The flow below is exercised end to end by `scripts/demo.sh` against the fake contract apps (see [TESTING.md](TESTING.md)).

```bash
API=http://127.0.0.1:8000

# 1. operator creates an account; the key is shown once
curl -s -X POST $API/admin/accounts -H "X-Admin-Key: $ADMIN_API_KEY" -H 'content-type: application/json' -d '{"name":"Acme"}'
# {"account":{"id":"..."},"api_key":"isk_xxxxxxxx_...","key_id":"..."}

# 2. register sources. Best: give both apps the SAME pepper first (PUT /api/v1/analytics/identity-pepper in each, see
#    APPROACH.md "Combining the two apps") and register that value for both. Apps that still have their own random
#    peppers need step 4.
curl -s -X POST $API/v1/sources -H "Authorization: Bearer $KEY" -H 'content-type: application/json' -H 'Idempotency-Key: src-funnels-1' \
  -d '{"kind":"funnels","name":"funnels","base_url":"https://funnels.example.com","api_key":"fa_live_...","identity_pepper":"..."}'

# 3. sync and train, then read
curl -s -X POST "$API/v1/sync?wait=true" -H "Authorization: Bearer $KEY" -H 'content-type: application/json' -d '{}'
curl -s -X POST "$API/v1/models/train?wait=true" -H "Authorization: Bearer $KEY" -H 'content-type: application/json' -d '{}'
curl -s "$API/v1/rankings/steps" -H "Authorization: Bearer $KEY"

# 4. only when the two apps have different peppers (not needed once they share one) (GET /v1/join shows joined_contacts 0 and a pepper warning):
#    send a contact list you already hold. E-mails are hashed in memory with each source's pepper and never stored.
curl -s -X POST $API/v1/identity/bridge -H "Authorization: Bearer $KEY" -H 'content-type: application/json' \
  -d '{"emails":["ada@example.com","grace@example.com"]}'
# {"emails_received":2,"emails_usable":2,"canonical_source_id":"...","links_by_source":{"...":2},"rooms_rekeyed":3}
curl -s -D- "$API/v1/segments" -H "Authorization: Bearer $KEY" -o /dev/null | grep -i etag
curl -s "$API/v1/segments" -H "Authorization: Bearer $KEY" -H 'If-None-Match: "<etag>"' -w '%{http_code}\n'   # 304

# 4. score a lead by email (hashed in memory, never stored)
curl -s -X POST $API/v1/leads/score -H "Authorization: Bearer $KEY" -H 'content-type: application/json' -d '{"email":"jane@example.com"}'

# 4b. batch scoring (up to 5000 rows)
curl -s -X POST $API/v1/leads/score/batch -H "Authorization: Bearer $KEY" -H 'content-type: application/json' \
  -d '{"features":[{"utm_source":"email","n_page_views_pre":4},{"utm_source":"facebook"}]}'

# 5. ask
curl -s -X POST $API/v1/ask -H "Authorization: Bearer $KEY" -H 'content-type: application/json' -d '{"question":"Which funnel should I fix first and why?"}'
```

### Errors
```json
{"error": {"code": "NOT_FOUND", "message": "source not found"}}
{"error": {"code": "VALIDATION_ERROR", "message": "question: String should have at least 3 characters"}}
{"error": {"code": "RATE_LIMITED", "message": "too many requests"}}
```
Codes in use: `UNAUTHORIZED`, `FORBIDDEN`, `NOT_FOUND`, `VALIDATION_ERROR`, `INVALID_INPUT`, `INVALID_SOURCE_URL`, `SOURCE_EXISTS`, `IDEMPOTENCY_MISMATCH`, `NO_ACTIVE_MODEL`, `NO_PREVIOUS_MODEL`, `UNKNOWN_MODEL_TYPE`, `BATCH_TOO_LARGE`, `COLUMNAR_DISABLED`, `ARTIFACT_INTEGRITY`, `JWT_DISABLED`, `KEY_REQUIRED`, `PAYLOAD_TOO_LARGE`, `RATE_LIMITED`, `INTERNAL_ERROR`.
